The Hospital Problem

Concept 1: CPU Priority Scheduling

Slide 04 / 10

4 Priority Triage Levels

  • P1 (Emergency Trauma): Highest priority (Heart attack, head injury). Preempts running CPU task immediately.
  • P2 (Urgent Surgery): High priority queue placement.
  • P3 (General OPD Ward): Standard doctor consultation.
  • P4 (Routine Checkup): Lowest priority queue.

Preemption & Aging Mechanism

  • Preemptive Context Switch: When a P1 patient arrives, the doctor CPU pauses lower priority tasks and handles P1 immediately.
  • Aging Counter: If a routine P4 patient waits in the queue for >10 ticks, aging logic boosts its priority to prevent starvation.

Concept 2: Process Control Block (PCB)

Slide 05 / 10

PCB Structure

  • PID: Unique ID (e.g., P101, P102)
  • Priority: Urgency level (P1 to P4)
  • Burst Time: Remaining treatment duration
  • Memory Required: Allocation in KB
  • Resource Claim: Equipment required (ICU, OR, MRI)
  • Metrics: Arrival, Wait & Turnaround times

Process 5-State Machine

Each patient process transitions through standard OS lifecycle states:

NEW ➔ READY ➔ RUNNING ➔ WAITING ➔ DONE

If an equipment lock is busy, the process stays in WAITING until freed.

Concept 3: Thread Synchronization & Mutexes

Slide 06 / 10

Shared Critical Equipment

  • ICU Bed Mutex: Exclusive single-patient access.
  • Ventilator Mutex: Critical respiratory support lock.
  • MRI Scanner Mutex: Diagnostic imaging suite lock.
  • Operating Room Mutex: Surgical suite critical section.

Preventing Race Conditions

Two patient tasks cannot book the same MRI scanner simultaneously.

Our code uses a Mutex class. When a patient process acquires the lock, status becomes LOCKED. Requesting processes move to the Waiting List without causing race conditions.

Concept 4: Banker's Algorithm & RAG Graph

Slide 07 / 10

Banker's Safety Verification

Before granting multi-resource equipment requests, the algorithm calculates matrices to ensure system safety:

  • Maintains Available, Max, Allocation
  • Computes Need = Max - Allocation
  • Verifies that a valid safe sequence exists

Resource Allocation Graph (RAG)

We render an interactive RAG graph on Canvas:

  • Circles = Patient Processes
  • Squares = Equipment Resources
  • Solid Arrows = Held Allocations
  • Dashed Arrows = Pending Requests
  • Auto-detects circular wait deadlocks.

Concept 5: Memory Allocation & Paging

Slide 08 / 10

Main Memory Allocation (RAM)

A 1024 KB memory block is managed to store active patient files:

  • First-Fit: Allocates in first open space.
  • Best-Fit: Minimizes internal fragment size.
  • Worst-Fit: Uses largest available block.
  • Adjacent free blocks merge upon discharge.

Virtual Memory Paging

Simulates accessing scan pages into 4 physical frames:

  • LRU (Least Recently Used): Evicts oldest unaccessed page.
  • FIFO: Replaces the oldest loaded page.
  • Live counters for Page Hits, Page Faults, and Hit Ratio.
